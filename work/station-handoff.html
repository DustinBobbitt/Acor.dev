The custody problem

A valid program can still be mishandled between the share and the machine.

Partial copies, stale network folders and ambiguous filenames can turn a correct generated artifact into an unsafe operational handoff. The station applications therefore treat loading as a state transition with source and staged identity—not as drag-and-drop convenience.

Release is separate from generation

A generated set stays in the library until an explicit release/assignment decision makes the intended machine format visible to a station. Omni receives TAP. Python receives XPR/NC. The station does not relabel one format as the other.

Local-first evidence

Status and issue records are written locally first so a lost network connection does not erase the operator's action. Later publication is an attempted synchronization, not a prerequisite for recording what happened on the station.

The operator remains the authority for the physical cycle

Read-only FOCAS or Syntec observations provide useful context and, under conservative rules, can support completion evidence. They do not turn the portfolio demo into a controller. The operator loads, sets up and runs the physical machine.
