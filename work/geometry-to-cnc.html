One geometry set. One canonical nest. Two machine formats.

The strongest part of this manufacturing suite is not a dashboard. It is a guarded transformation chain that interprets supported machining recipes, publishes complete geometry sets atomically and posts independent programs for two controller families.

The manufacturing problem

Geometry cannot be “close enough.”

Cabinet part rows carry dimensions and references to machining recipes. Those recipes can describe outlines, mirrored parts, bores, line bores, pockets and routes. A generator that guesses an unfamiliar operation can produce a syntactically valid file that is physically wrong.

The implementation therefore treats recipe support as an admission gate. Known, captured forms are resolved explicitly. An unknown reference or unsupported active operation refuses the set before it reaches the published output directory.

Atomic geometry publication

All expected DXFs are generated into staging. Only a complete, validated set replaces the prior output. A failure in one part cannot leave a directory that looks complete but silently omits machining.

One layout, independent programs

The direct post reads the DXF set, expands quantities, separates saw-owned parts, groups material and thickness, and produces canonical sheets. Both machine-format emitters receive that same sheet definition. TAP is not renamed into XPR, and imported TAP is not treated as convertible production truth.

Each format records its own outcome. TAP may succeed while XPR is unavailable, or the reverse. The manifest preserves the distinction so downstream release logic can select only a verified format.

What the public demonstration will show

  1. A newly authored synthetic part with supported outline, bore and route operations.
  2. Successful atomic DXF generation and a visual geometry preview.
  3. One canonical sheet definition feeding two separate posts.
  4. Independent hashes, program lists and format status.
  5. A second part with an unsupported operation being refused before publication.

Boundary

What this does not prove

Source tests and generated programs do not establish tooling, hold-down, collision clearance, controller acceptance or dimensional quality on a physical machine.
