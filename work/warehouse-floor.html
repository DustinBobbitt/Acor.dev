A warehouse map that knows what's on every shelf.

Warehouse Floor draws a facility as one connected building—departments, walls, doors, racks and floor zones—and ties layout changes, counts, pallets and stock search to that same map. I designed and built it for a working manufacturing warehouse. Everything on this page is a fictional facility with invented stock.

Why it exists

A count is only useful if you can find the shelf it describes.

In a working warehouse, the layout, the inventory and the people counting it drift apart. Racks move, bays get added, and a count sheet stops matching the floor. Warehouse Floor keeps one model of the building and attaches everything else to it.

Every rack location has a stable identity, so a count, a pallet or a search result always points at a real place—even after the layout around it changes.

How it works

Three everyday jobs, one map.

01 · LAYOUT

Change the layout without touching live stock.

Drag a rack, rotate it or add a new one from the equipment picker. Every edit is saved to a numbered draft, with undo and redo, while the working map stays exactly as it was.

Review lists the changes in plain language—"Added rack S5 in Shipping," "Moved rack R4"—before Apply makes them real.

02 · COUNT

Count where the stock actually lives.

Open any rack to see it the way it stands on the floor: bays across, levels up. Record one product or several in a bay, then save and step to the next bay.

A location you checked and found empty is marked differently from one nobody has counted yet, so a blank cell never passes for a confirmed zero.

03 · FIND & MOVE

Find it, then move it.

Search an item number across every department and jump straight to the bay that holds it.

Pallets carry their contents, so dragging one across the floor keeps its product and quantity attached. Reload the app and everything is where you left it.

Design decisions

Built so a mistake on the map can't become a mistake in the stock.

Drafts, not live edits

Layout changes go into a draft with its own revision number. Saving a draft never changes the working map; only a reviewed Apply does. Revisions are checked, so an out-of-date draft can't silently overwrite newer work.

Layout and inventory stay separate

Pallet adds and moves go through their own plan, and counts stay in the inventory store. Undoing a layout edit can never rewrite live inventory.

One place, two modes

The inventory view and the layout editor share one scene and hand the camera back and forth, so switching from counting to editing keeps you looking at the same department.

Made for the shop's hardware

Windows 7 shop PCs, both 32- and 64-bit, are a required target, so the code stays compatible with Python 3.8 and older browsers. Data lives on a shared folder or in SQL Server so several workstations see the same warehouse.

Current status

Still moving

In active development. The browser layout editor is an opt-in preview alongside the original desktop editor, and testing on physical Windows 7 machines is still open.
